# Reports

## Purpose
Analytics over `Submission`/`Answer` data for a given `Form`, plus document export of that analytics. Split into `Queries/` (compute statistics, return DTOs) and `Commands/` (re-run the matching query, then hand the result to `IReportGenerator` to produce a downloadable `byte[]` document — typically for a controller to return as a file). `Queries/Shared/` holds the filter model, filter-application logic, name-resolution logic, and the median/mean/mode/standard-deviation math reused by every analytics query so the four query handlers don't duplicate it.

All statistics operate only on **numeric** answers (`Answer.Value == null && Answer.NumericValue != null`), i.e. `QuestionType.Number` and `QuestionType.WeightedRating`. Text/choice answers are excluded from statistics entirely (they're surfaced separately by `GetAdvices`). Calculation follows "Методика оценки удовлетворенности потребителей" (college-specs/Методика_оценки.md, section 5.6): each answer is a `(Score, Weight)` pair — `Weight` defaults to `10` (max importance) when the question has no explicit importance weight (plain `Number` questions) — and `StatisticsCalculator` computes `SatisfactionPercentage` as the mean of `Score/Weight` ratios across respondents x100 (formula 1), `AverageScore`/`StandardDeviation` from the raw scores (formulas 2-3), and `Rating` by thresholding `SatisfactionPercentage` against Table 1 (&lt;40/&lt;60/&lt;80/&ge;80 -> Unsatisfactory/Satisfactory/Good/Excellent). Building the `(Score, Weight)` pair list is duplicated inline in `GetAnalyticsByGroups`, `GetAnalyticsByPeriod`, and `GetAnalyticsByPeriods` handlers (not factored into `Shared/`, so keep it in sync if the formula ever changes). Overall (across-question) aggregates — mean of `SatisfactionPercentage` and mean of `StandardDeviation` per formulas 5-6 — are **not** computed server-side; they're derived client-side in `Web.Client`'s admin-stats-page from the per-question `QuestionStatistics` list.

| `Queries/Shared/EntityNameResolver.cs` | `public static class` with `ResolveFilterNamesAsync(AnalyticsFilterSet, IApplicationDbContext, ILogger, ct) : Task<Dictionary<string,string>>` — resolves every filter id in an `AnalyticsFilterSet` to a human-readable Russian-labeled name (`"Преподаватель"`, `"Дисциплина"`, `"Кафедра"`, `"Специальность"`, `"Специализация"`, plus raw string filters `"Организация"`, `"Форма обучения"`, `"Категория сотрудника"`, `"Должность"`), loading all five entity lookups in parallel via `Task.WhenAll`, falling back to the raw GUID string (with a `LogWarning`) if an id doesn't resolve, and catching any exception to fall back to GUIDs for *all* filters with a `LogError`. | `Queries/GetAdvices/` | `GetAdvicesQuery(FormId, TeacherId?) : IQuery<List<GetAdvicesQueryResponse>>`. Not statistical — pulls every non-empty **text** answer (`Answer.Value != null && != ""`) across all submissions for the form (optionally scoped to one teacher), returning `(Text, TeacherId?, DepartmentId?)` per answer. This is how free-text "advice"/comments are surfaced to reviewers. |
| `Queries/GetAnalyticsByGroups/` | `GetAnalyticsByGroupsQuery(FormId, FromDate, ToDate, GroupingType, AnalyticsFilterSet) : IQuery<List<GetAnalyticsByGroupsQueryResponse>>`. `GroupingType` enum: `Department, Discipline, Speciality, Specialization, EducationForm, EmployeeCategory, Teacher`. Filters submissions by date range (`ToDate` treated as inclusive via `+1 day`) and `AnalyticsFilterSet`, projects to a lightweight `SubmissionProjection` (avoids loading full entities), groups by the requested dimension (entity-backed dimensions resolve display names via `EntityNameResolver`'s bulk resolvers; `EducationForm`/`EmployeeCategory` group by the raw string value, falling back to `"Unknown"`), then computes `QuestionStatistics` per group from that group's numeric answers. Ungrouped/unmapped `Guid.Empty` keys display as `"Не указано"`. |
| `Queries/GetAnalyticsByPeriod/` | `GetAnalyticsByPeriodQuery(FormId, FromDate, ToDate, AnalyticsFilterSet) : IQuery<List<GetAnalyticsByPeriodQueryResponse>>`. Single-period statistics per question — no grouping dimension. Filters by date range (inclusive `ToDate`) and `AnalyticsFilterSet` via `SubmissionFilterHelper`, groups numeric answers by `QuestionId`, computes stats. |
| `Queries/GetAnalyticsByPeriods/` | `GetAnalyticsByPeriodsQuery(FormId, List<GetAnalyticsByPeriodsRequest>) : IQuery<List<GetAnalyticsByPeriodsQueryResponse>>` where `GetAnalyticsByPeriodsRequest(Label, DateFrom, DateTo, AnalyticsFilterSet)`. Runs the same per-period logic as `GetAnalyticsByPeriod` in a loop (`ProcessPeriod` private method), once per requested period, each period free to have its own date range **and its own filter set** — this is the "compare N custom periods side by side" query, distinct from `GetAnalyticsByGroups`' "compare N groups within one period" query. Returns one `GetAnalyticsByPeriodsQueryResponse(Label, PeriodStart, PeriodEnd, List<QuestionStatistics>)` per period, even if a period has zero matching answers (empty `QuestionStatistics` list, not omitted). |
| `Queries/Shared/` | See Key Files above. |

## For AI Agents
### Working In This Directory
- All four query handlers independently re-implement "validate form exists -> Result.Failure(FormErrors.NotFound) if not" and "load numeric answers -> group -> StatisticsCalculator" — if you add a fifth analytics query, follow the same shape rather than trying to unify it into one generic handler; the codebase treats each as a distinct, independently evolvable read model.
- The three `Export*CommandHandler`s all follow the same 4-5 step shape: (1) build the matching `Query` and call its `IQueryHandler<,>` directly (constructor-injected, not resolved via a mediator — this is a deliberate direct-call composition, so if you add a new export command, inject `IQueryHandler<TYourQuery, TYourResponse>` the same way), (2) re-load the `Form` for its `Title` (a second DB round-trip — the query handler doesn't return the title), (3) log-and-continue on empty results rather than failing, (4) optionally resolve human-readable filter names, (5) call the matching `IReportGenerator` method inside a `try/catch` that rethrows `OperationCanceledException` but converts any other exception into `Result.Failure(Error.Failure("Report.GenerationFailed", "Failed to generate report"))`. All three handlers are `sealed partial class` using `[LoggerMessage]` source-generated logging methods — follow that pattern (declare `static partial void LogXxx(...)` methods with `[LoggerMessage(LogLevel.X, "template {param}")]`) rather than calling `logger.LogInformation(...)` inline, to match the existing style in this subfolder.
- Building the `(Score, Weight)` pair (`Weight = a.Weight ?? 10m`) is copy-pasted across `GetAnalyticsByGroups`, `GetAnalyticsByPeriod`, and `GetAnalyticsByPeriods`. If you change the default-weight fallback, update all three (and consider finally factoring it into `Queries/Shared/`).
- New grouping dimensions for `GetAnalyticsByGroups` require: adding a `GroupingType` enum member, a case in the `GroupSubmissionsAsync` switch, and (if it's an entity-backed dimension rather than a raw string like `EducationForm`) a `GroupBy{Dimension}Async` private method following the existing `GroupByDepartmentAsync`/`GroupByDisciplineAsync`/etc. pattern (resolve names in bulk via `EntityNameResolver`, then `GroupBy(id ?? Guid.Empty)` with `"Не указано"` fallback).
- UI-facing strings here (Russian filter labels, `"Не указано"`, `"Unknown"` for missing EducationForm/EmployeeCategory) are inconsistent in language (`"Не указано"` vs `"Unknown"`) — be aware of this if asked to make labels consistent, but don't "fix" it silently since it may be relied upon by the frontend.
