

# Система Анкетирования (Anketa Project)

Этот проект представляет собой полную переработку и модернизацию существующей системы анкетирования, изначально написанной на PHP. Новая система разрабатывается на стеке ASP.NET Core и React с применением принципов чистой архитектуры (Clean Architecture) для создания надежного, масштабируемого и поддерживаемого решения.

> 📋 **Для полного описания проекта, включая детальный анализ реализованных и недостающих компонентов, см. [PROJECT_DESCRIPTION.md](./PROJECT_DESCRIPTION.md)**

## 1. Техническое Задание (ТЗ)

### 1.1. Цель проекта

Создать веб-приложение для проведения опросов и анкетирования среди различных групп пользователей (студенты, сотрудники, работодатели) с целью сбора и анализа данных об удовлетворенности образовательным процессом и другими аспектами деятельности учебного заведения.

### 1.2. Основные возможности

-   **Аутентификация и авторизация:** Безопасный вход в систему для разных категорий пользователей.
-   **Управление анкетами:** Администраторы могут создавать, редактировать и управлять анкетами и вопросами.
-   **Прохождение анкетирования:** Авторизованные пользователи могут просматривать доступные им анкеты и отправлять свои ответы.
-   **Аналитика и отчеты:** Администраторы и заведующие кафедрами могут просматривать агрегированные данные, применять фильтры и выгружать отчеты.

### 1.3. Роли пользователей

| Роль | Описание |
| :--- | :--- |
| **Администратор** | Полный доступ ко всем функциям системы: управление пользователями, анкетами, просмотр всех отчетов. |
| **Зав. кафедрой** | Просмотр аналитики и отчетов в рамках своей кафедры. |
| **Студент** | Прохождение анкет, предназначенных для студентов. |
| **Сотрудник** | Прохождение анкет, предназначенных для персонала. |
| **Работодатель** | Прохождение анкет, касающихся качества подготовки выпускников. |

### 1.4. Ключевые фичи

-   **Динамический конструктор анкет:** Возможность создавать анкеты с разными типами вопросов.
-   **Типы вопросов:**
    -   **Оценка с весом:** Пользователь указывает "важность" критерия (макс. оценку) и саму оценку.
    -   **Текстовый ответ:** Свободный ввод текста.
    -   **Выбор вариантов:** Выбор одного или нескольких вариантов из предложенных.
-   **Гибкая фильтрация отчетов:** Возможность фильтровать результаты по дате, кафедре, специальности, преподавателю и другим контекстным параметрам.
-   **Сравнительный анализ:** Функция для сравнения данных за разные периоды (например, текущий год с предыдущим).
-   **Экспорт данных:** Возможность выгрузки отчетов в формате `.docx`.

### 1.5. Технологический стек

-   **Backend:** ASP.NET Core
-   **База данных:** PostgreSQL
-   **ORM:** Entity Framework Core (Code-First)
-   **Архитектура:** Clean Architecture
-   **Паттерны:** CQRS (с использованием MediatR), Repository, Unit of Work
-   **Аутентификация:** JWT (JSON Web Tokens)
-   **Frontend:** React (с использованием TypeScript)

## 2. Архитектура и Нюансы Реализации

### 2.1. Clean Architecture

Проект строго разделен на 4 слоя для обеспечения независимости бизнес-логики от деталей реализации:
-   `Domain`: Сущности и ключевые бизнес-правила. Не зависит ни от чего.
-   `Application`: Сценарии использования (Use Cases), команды, запросы. Зависит только от `Domain`.
-   `Infrastructure`: Реализация внешних зависимостей (база данных, генерация токенов). Зависит от `Application`.
-   `Api`: Точка входа (контроллеры), конфигурация. Зависит от `Application` и `Infrastructure`.

### 2.2. Двухуровневая валидация: Frontend + Backend

Для обеспечения как отличного пользовательского опыта, так и целостности данных, применяется двухуровневая валидация.

**Пример:** Валидация оценки на основе "веса" (максимальной оценки).

#### Frontend (React)

На стороне клиента мы динамически ограничиваем ввод, чтобы пользователь не мог совершить ошибку. Это делает интерфейс отзывчивым.

```jsx
import React, { useState } from 'react';

const RatingQuestion = ({ questionText }) => {
  const [weight, setWeight] = useState(10); // "Вес" или максимальная оценка
  const [mark, setMark] = useState(5);     // Сама оценка

  const handleWeightChange = (e) => {
    const newWeight = parseInt(e.target.value, 10) || 0;
    setWeight(newWeight);

    // Если текущая оценка больше нового максимума, сбрасываем ее
    if (mark > newWeight) {
      setMark(newWeight);
    }
  };

  return (
    <div>
      <p>{questionText}</p>
      <div>
        <label>
          Важность (макс. оценка):
          <input type="number" value={weight} onChange={handleWeightChange} min="1" max="10" />
        </label>
      </div>
      <div>
        <label>
          Ваша оценка:
          <input 
            type="number" 
            value={mark} 
            onChange={(e) => setMark(parseInt(e.target.value, 10))}
            min="0"
            // Атрибут max динамически привязан к состоянию weight
            max={weight} 
          />
        </label>
      </div>
    </div>
  );
};
```

#### Backend (ASP.NET Core)

Сервер **всегда** выполняет финальную проверку. Это гарантирует, что бизнес-правило не будет нарушено, даже если запрос отправлен в обход UI.

```csharp
// В обработчике команды сохранения ответа
foreach (var detailDto in command.Details)
{
    if (detailDto.Mark.HasValue && detailDto.Weight.HasValue && detailDto.Mark > detailDto.Weight)
    {
        return Error.Validation(
            code: "Answer.InvalidMark",
            description: $"Оценка по вопросу {detailDto.QuestionId} не может быть больше веса.");
    }
}
```

### 2.3. Обработка ошибок

Вместо использования исключений для контроля потока выполнения, проект использует библиотеку `ErrorOr`. Это позволяет обработчикам в `Application` слое возвращать либо успешный результат, либо типизированный список ошибок, которые затем преобразуются в корректные HTTP-ответы (400, 404, 409 и т.д.) в `Api` слое.

## 4. Запуск Проекта

### 4.1. Необходимые инструменты
-   .NET 9 SDK
-   PostgreSQL Server
-   Git

### 4.2. Настройка
1.  Склонируйте репозиторий.
2.  Создайте базу данных в PostgreSQL.
3.  Скопируйте `appsettings.Development.json.template` в `appsettings.Development.json` в проекте `Questionnaire.Api`.
4.  Заполните вашу строку подключения `DefaultConnection` в `appsettings.Development.json`.
5.  Выполните команды в терминале из корневой папки проекта:

    ```bash
    # Установка зависимостей
    dotnet restore

    # Применение миграций к базе данных
    dotnet ef database update -s src/Questionnaire.Api

    # Запуск приложения
    dotnet run --project src/Questionnaire.Api
    ```
Приложение будет доступно по адресу `http://localhost:5202`. Swagger UI — по адресу `http://localhost:5202/swagger`.



Отличное дополнение. Включение исторического контекста очень важно. Это поможет нам правильно спроектировать новые сущности и обеспечить миграцию данных в будущем, если это потребуется.
