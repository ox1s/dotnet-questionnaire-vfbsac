# 📄 Техническое Задание: Система Анкетирования

## 1. Общие положения

Веб-приложение для проведения анонимного анкетирования студентов, сотрудников и работодателей с целью оценки качества образования. Система заменяет бумажные анкеты, сохраняя привычную методику расчета баллов.

## 2. Пользователи и Доступ

### 2.1. Аутентификация

- **Тип:** Групповая / Ролевая.
- **Регистрация:** Отсутствует для пользователей. Учетные записи создает Администратор вручную.
- **Роли:**
  1.  **Администратор:** Полный доступ, управление справочниками (преподаватели, предметы, группы), создание пользователей.
  2.  **Студенческая группа (UserRole.StudentGroup):** Логин/пароль выдается на группу (например, логин `39TP`, пароль `123`). Анонимность внутри группы полная.
  3.  **Сотрудник (UserRole.Staff):** Персональный или кафедральный аккаунт.
  4.  **Работодатель (UserRole.Employer):** Аккаунт выдается представителю компании.

### 2.2. Анонимность

- При сохранении анкеты (Submission) сохраняется deviceId (для предотвращения повторной отправки одной и той же формы в рамках ip), но в отчетах для кафедры/преподавателя персонализация полностью скрыта.
- Сохраняется дата прохождения (`SubmittedAt`) для аналитики по семестрам.

## 3. Функциональные требования

### 3.1. Конструктор Анкет (Admin Panel)

Администратор создает анкеты. Ключевая особенность — поддержка Legacy-типов вопросов.

**Типы вопросов:**

1.  **Оценка с весом (Weighted Rating):**
    - Пользователь вводит два значения:
      1.  **Важность (Вес):** Насколько этот критерий важен для него (от 1 до 10).
      2.  **Оценка:** Реальная оценка преподавателя/предмета.
    - **Валидация:** Оценка не может быть больше Важности (Оценка ≤ Важность).
2.  **Текстовый ввод (Text):** Для предложений и замечаний.
3.  **Выбор вариантов (Checkbox/Radio):** Для вопросов типа "С какими трудностями столкнулись?".
4.  **Числовой ввод (Number):** Обычная оценка (1-10) без веса.

### 3.2. Процесс прохождения (UI Студента)

1.  Студент авторизуется под логином группы.
2.  Видит список доступных анкет (например, "Преподаватель глазами студента").
3.  При выборе анкеты, если она требует контекста (оценка конкретного лица), система предлагает выбрать из выпадающего списка:
    - **Дисциплину** (из справочника).
    - **Преподавателя** (из справочника).
4.  Студент заполняет форму.
5.  После отправки редактирование невозможно.

### 3.3. Справочники (Context)

Админ вручную наполняет справочники внутри системы:

- Кафедры (Departments)
- Дисциплины (Disciplines)
- Преподаватели (Teachers)
- Специальности (Specialities)

## 4. Аналитика и Отчеты

### 4.1. Расчет баллов (Методика)

Для вопросов типа "Оценка с весом":

- Система хранит пару значений: `(Weight, Value)`.
- Итоговый балл по вопросу (для отчета) считается как среднее арифметическое или сумма.

### 4.2. Виды отчетов

1.  **Индивидуальный отчет:** По конкретному преподавателю/дисциплине за период.
2.  **Сравнительный отчет (Period vs Period):** Сравнение показателей (например, средний балл) за текущий год vs прошлый год.
3.  **Сравнительный отчет (Unit vs Unit):** Кафедра А vs Кафедра Б.
4.  **Экспорт:** Генерация файла `.docx` (Word) с таблицами и итоговыми цифрами.

### 4.3. Доступ к аналитике

- **Админ:** Видит всё.

### 4.4. Фильтры для администратора

1. **Скачивание анкеты:** При выборе преподавателей либо же предметов должна существовать фильтрация по полям:
   - специализация
   - специальность
   - кафедры
   - предметы
